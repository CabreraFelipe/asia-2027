# Document sanitizer (candidate, no deployment)
The CLI reconstructs visible pages as a raster-only PDF (up to 10 pages, max 2200 px on longest side) or re-encodes a single PNG/JPEG, stripping source metadata. Original files are never sent to the model by this service. Encrypted, JavaScript-bearing, damaged, oversized and animated inputs are rejected. Rendering may omit hidden or nonvisual information and may reduce readability; review against the original is mandatory. This is not a malware scanner or a guarantee against parser vulnerabilities.
Run a fresh container per request, with no network, no secrets, no host mounts, read-only root, nonroot user, dropped capabilities, no-new-privileges, strict CPU/memory/pid and temporary-file limits, and mandatory external deadline with container termination. Example CI settings: --network none --read-only --cap-drop ALL --security-opt no-new-privileges --pids-limit 32 --memory 512m --cpus 1 --tmpfs /tmp:rw,noexec,nosuid,size=96m.
The trusted private service must stream only the requested bytes to stdin, cap input/output, enforce a deadline even if client disconnects, parse the first JSON line (max 512 bytes), verify exact output length, and return binary with Content-Type, X-Asia-Inspector: raster-v1, X-Asia-Pages, plus X-Asia-Width/Height for images. Never log input or parser output. A failed/aborted process must not return a successful result. No shared persistent storage. No access to the Docker socket from a public service. Before production: use a dedicated hardened runtime (prefer stronger isolation than a shared container kernel), pin audited image/dependencies, vulnerability and license review, test malformed/encrypted/active and real documents, enforce independent concurrency and retention, and provision a private authenticated service binding. The service host is not implemented or deployed by this commit.
