# V11.27 — integración de Storage con el frontend original
Candidato sin despliegue. V11.24 permanece activa. Se corrige el runner Chrome V11.26: importación estática en el HTML de test, no import relativo desde Runtime.evaluate. Se añade bridge explícito para claves portables, dispositivo temporal (no persistente), rechazo de credenciales y claves desconocidas, coordinador de guardado serializado con propagación de errores. No se ha cambiado main ni ningún archivo original en raíz.
La prueba CI abre index.html original en iframe local sintético, con un preload exclusivo de test que sustituye Storage y factory IndexedDB en esa ventana; se bloquean conexiones externas y service worker. Usa la definición de cuenta original para separar IndexedDB modular, que NO está cifrada aún y NO es apta para datos reales. El test ejercita control original de altura, navegación Dieta/Gym, guardado y recuperación de dos cuentas. Autenticación simulada, no Google real. No es mecanismo de producción ni prueba de paridad. El bridge no persiste las claves de dispositivo (pendiente), y las acciones originales todavía pueden informar éxito antes de flush; falta conectar un estado de guardado durable, recuperación de conflictos y lifecycle real. No usar datos reales ni desplegar.
