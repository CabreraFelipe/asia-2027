# V11.26 — almacenamiento local cifrado candidato
Continúa V11.25; V11.24 permanece activa. V10.6 original y main no modificados.
Se agrega session-vault.mjs, que consume /v11.11/auth/me de staging, reutiliza policy.portable de accounts106.js y encrypt84/decrypt84 de model84.mjs, persiste solo ciphertext por cuenta en una nueva IndexedDB con CAS atómico y proporciona interfaz síncrona de Storage explícita. Sin modificar globals, sin migración, sin credenciales antiguas. Flush explícito, conflicto no sobreescribe, cambio de sesión invalida memoria. No es barrera contra código malicioso same-origin; el chequeo de sesión es puntual, no continuo, y el cierre forzado puede perder cambios no guardados. No usar datos reales.
Pruebas CI: dos cuentas, claves portables, restauración, frase errónea, conflicto, cambio de sesión y transporte; CAS en memoria, IndexedDB de navegador y montaje en DOM original pendientes. El adapter no está conectado aún a las llamadas directas a localStorage, ni al IndexedDB original de módulos. Falta integrar flush con acciones y cierre, recuperación, lifecycle de pestañas, storage de módulos, y servicios externos; no presentar como aplicación terminada. Próximo: inventario completo de claves y llamadas, pruebas reales de navegador, integración mínima y explícita con frontend original. No desplegar este candidato.
